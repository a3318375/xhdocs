记录 NAS（`192.168.5.3`，栈目录 `/volume3/docker/file/stacks/`）上**换掉/冗余但保留配置与数据**的服务，重点记**当初为什么不用它**——方便以后翻查，避免重复试错。

栈的部署方：由 **Dockhand**（跑在 `192.168.5.5` 路由器上，容器 `dockhand`，数据落 NAS 的 PostgreSQL `5433/dockhand`）管理；栈文件在路由器 `/opt/dockerfile/dockhand/data/stacks/nas/<栈>/compose.yaml`，NAS 侧由 `hawser` 容器把 `/volume3/docker/file/stacks` 挂成 `/data/stacks`。**在 Dockhand 里删栈 = 两边目录里的 `compose.yaml` 一起消失。**

备份规格：
- **知识库快照（必做）**：`raw/configs/<name>-compose-<YYYYMMDD>.yaml`（raw frontmatter + body 与源文件逐字节一致 + sha256 自校验）
- **NAS 现场副本（可选）**：`<stack>/compose.yaml.bak-<YYYYMMDD-HHMMSS>`（与源文件同目录，md5 一致）
- 用户口径（2026-10-09）：**不要往 3 盘额外写备份副本**；服务配置归档进知识库即可。栈目录本身保留不删，恢复即 `docker compose up -d`
- 用户口径（2026-10-16 修正）：现场副本会**随 Dockhand 删除一起消失**，所以「知识库快照」是唯一可靠留存；9-27 迁移前做过全量归档 `/volume3/backup/pre-cwnas-20260927-204407/volume3-docker-file.tar.zst`（29.8GB，含 `docker/file` 全部栈文件），可作为最后兜底

## 服务清单

### litepan（旧配置）
- 镜像与入口：`ponphil/litepan:beta`，端口 `5211`；`privileged: true` + `/dev/fuse` + `pid: host`
- 挂载：`litepan/data`、`stacks/emby/media/strm`（STRM 输出目录）、`litepan/mounts`
- 接入网盘：115（`115_open` 驱动）、夸克（`quark` 驱动）
- 快照：`raw/configs/litepan-compose-20261009.yaml`（sha256 `c63e3fd4…`）；NAS 副本 `compose.yaml.bak-20261009-102233`
- **换掉的原因（2026-10-09 评估）**：
  - **秒传能力很受限**：只有固定几个网盘之间可用，本质依赖 OpenList 驱动（跨盘不存在真正的秒传，只能实下载再上传）
  - **STRM 生成与既有链路重叠**：`ani-rss → 115 → TgtoDrive(整理+STRM) → Emby` 已经在做，且更细（TMDB 正则、洗版、季集结构）
  - 实测运行状态：Up 4 天期间日志只有定时认证刷新，**无任何整理/秒传活动**
  - 结论：*"感觉功能不太实用"* → 评估为冗余，去留待定

### alist（旧配置）
- 镜像：`xhofe/alist:latest-aio`（`user: 0:0`），端口 `5244`，挂 `/volume3/docker/file/stacks/alist/data` 与 `/volume3/data`
- 现状（2026-10-09 检查）：容器状态 **`Created`**（早已不再运行）；功能位由 **OpenList**（`openlistteam/openlist:v4.2.3-aria2`，同为 5244）承担
- 快照：`raw/configs/alist-compose-20261009.yaml`（sha256 `9140baf7…`）；NAS 副本 `compose.yaml.bak-20261009-103031`
- **换掉的原因（2026-10-09 口述）**：
  - **优点**：支持一些**很稀少、不常见的网盘**——这是它相对 OpenList 的独特价值
  - **换掉**：因 **AList 与 OpenList 之间的风波**（项目归属/维护争议）导致不再常用
  - 即：淘汰原因是**生态/维护层面**，不是功能本身不行

## Practical takeaways
- 三个服务的淘汰逻辑不同，别混为一谈：
  - **litepan = 功能重叠 + 被驱动能力卡住**（技术性冗余，换个更强的整理器就能替代）
  - **alist = 生态风波**（能力本身仍有价值，但社区/维护风险让它不值得继续押注）
  - **tgtodrive = 用户决定停用（2026-10-09），理由待补**
- 网盘挂载 + 聚合这类需求，当前统一由 **OpenList** 承担。
- 整理 + STRM 生成这条链路，现状由 **TgtoDrive** 承担（`ani-rss → 115 → TgtoDrive(整理+STRM) → Emby`），与 litepan 的能力重叠。
- 保留「能力清单 + 换掉的理由」比保留「服务本身」便宜：以后遇到稀有网盘需求时，翻这里就能判断要不要把 alist 拉回来试。
